# 02. Интерфейсы

В Java класс пишет `implements Sink`. В Go тип удовлетворяет интерфейсу сам, если у него есть нужные методы. Объявлять ничего не надо.

Задача:
- `MemorySink` запоминает все обновления в поле `Got`. Метод `Send` должен быть на **указателе** (`func (s *MemorySink) Send`), иначе изменения пропадут: метод на значении получает копию.
- `FailingSink` всегда возвращает свою ошибку `Err`. Тут метод на **значении** (`func (s FailingSink) Send`): состояние не меняется, а тест кладёт в список `FailingSink{...}` без `&`.
- `SendAll` отправляет обновление во все приёмники. Ошибка одного не останавливает остальных. Вернуть все ошибки разом через `errors.Join`, или `nil`, если ошибок не было.

Что почитать: [Go by Example: Interfaces](https://gobyexample.com/interfaces), [Methods: pointer vs value receivers](https://go.dev/tour/methods/4).

Проверка на этапе компиляции, что тип реализует интерфейс, выглядит так: `var _ Sink = (*MemorySink)(nil)`. Она уже есть в тесте. Поэтому сначала пакет даже не скомпилируется: методов `Send` пока нет. Это первая ошибка, которую ты исправишь.
