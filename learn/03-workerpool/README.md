# 03. Пул воркеров

В Java ты бы взял `Executors.newFixedThreadPool(4)` и собрал `Future`. В Go горутины дешёвые, но запускать по горутине на каждую задачу без ограничения нельзя: упрёшься в базу или в лимиты.

Задача: `Map` применяет `fn` к каждому элементу, одновременно работают не больше `workers` горутин. Порядок результатов совпадает с порядком входа. `workers <= 0` считать за 1.

Подсказки:
- Результат удобно писать в заранее созданный срез по индексу: `out[i] = fn(items[i])`. Разные горутины пишут в разные ячейки, гонки нет.
- Ограничить параллелизм можно двумя способами: N горутин читают индексы из канала, или семафор из буферизованного канала `make(chan struct{}, workers)`.
- Дождаться всех: `sync.WaitGroup`.

Тест проверяет и результат, и то, что одновременно работало не больше `workers` горутин, но больше одной.

Что почитать: [Go by Example: Worker Pools](https://gobyexample.com/worker-pools), [WaitGroups](https://gobyexample.com/waitgroups).
