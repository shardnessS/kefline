# 06. Очередь, которая не блокирует отправителя

Это заготовка очереди клиента в gateway. Отправитель (раздача изменений) не должен ждать медленного клиента. Если очередь клиента полна, значение выбрасывается, а счётчик выброшенных растёт. По этому счётчику gateway потом решит отключить клиента.

Задача: `Queue` с ёмкостью `capacity`.
- `TryPush(v)` кладёт значение без ожидания. Очередь полна: вернуть `false`, увеличить счётчик `Dropped`.
- `Pop(ctx)` ждёт значение. Если `ctx` закончился раньше, вернуть `ok == false`.
- `Len()` — сколько значений лежит сейчас.
- Безопасна для вызова из многих горутин.

Подсказки:
- Буферизованный канал уже и есть очередь ограниченного размера.
- Отправка без ожидания: `select` с веткой `default`.
- Счётчик: `atomic.Int64` из `sync/atomic`.
- `Len()` для канала: встроенная `len(ch)`.

Что почитать: [Go by Example: Non-Blocking Channel Operations](https://gobyexample.com/non-blocking-channel-operations), [Atomic Counters](https://gobyexample.com/atomic-counters).
