# 07. Склейка изменений

Коэффициент исхода за секунду может поменяться десять раз. Клиенту, который не успевает, нужно только последнее значение. Склейка (conflation) держит по одному ожидающему изменению на ключ и заменяет его новым.

Задача: `Conflator`.
- `Put(ch)`: если изменение с таким `Key` уже ждёт, заменить его. Позиция в очереди остаётся старой, а значение и версия новые. Счётчик `Merged` растёт.
- Пришло изменение с версией меньше ожидающей: это опоздавшее сообщение, его игнорируем, ожидающее не трогаем.
- `Drain()` возвращает ожидающие изменения в порядке первого появления ключей и очищает склейку.
- Безопасен для вызова из многих горутин.

Подсказки:
- Порядок плюс быстрый поиск по ключу: срез ключей `[]string` и мапа `map[string]Change`.
- Защита: `sync.Mutex`, `Lock` и `defer Unlock` в каждом методе.
- `Drain` должен вернуть новый срез, а внутреннее состояние сбросить. Не отдавай наружу внутренний срез.

Что почитать: [Go by Example: Mutexes](https://gobyexample.com/mutexes), [Maps](https://gobyexample.com/maps).
